Fetching Data

Six lessons. Do 1–4 by hand before touching any library.

The analogy throughout: your browser is a customer, the API server is a restaurant kitchen, and a request is an order.

1 fetch: ordering for yourself ✓ complete

Analogy
You phone the kitchen yourself. Food arrives in a sealed bag. You open it (res.json()) and check it's actually your order (res.ok). If the kitchen says "we're out of that" (a 404 or 500), the phone call still succeeded, so fetch won't complain. It only fails if the phone line is dead (a network error).

What it really is
A function built into the browser. It returns a promise, so everything from the promises quiz applies here.

2 Headers: the notes on the order slip ✓ complete

Analogy
The food is the body. Headers are the notes clipped to the order: "I want it boxed" (Accept: application/json), "here's my membership card" (Authorization), "this is soup" (Content-Type). The kitchen clips its own notes to the reply: "eat within 10 minutes" (Cache-Control).

What it really is
Key-value metadata about the request or response. It describes the data but isn't the data.

3 CORS: the strict parent ✓ complete

Analogy
The browser is a strict parent. Your page (a kid from house A) orders from kitchen B. The parent asks kitchen B, "do you serve kids from house A?" If kitchen B's reply doesn't include Access-Control-Allow-Origin: A, the parent takes the food away. Often the order already reached the kitchen; you just aren't allowed to eat it. For some orders, the parent phones ahead first. That's the "preflight" OPTIONS request.

What it really is
CORS (Cross-Origin Resource Sharing) is a browser-only safety rule. Server-to-server calls, and tools like curl or Postman, have no parent, so there's no CORS.

4 Reverse proxy: your own waiter ✓ complete

Analogy
Instead of ordering from kitchen B directly, you give your order to a waiter in your own house. The waiter walks it over to kitchen B. The parent sees you ordering at home, so CORS doesn't apply. The waiter also holds the membership card, so you never see the secret key.

What it really is
A server between your app and the real API that forwards requests. It's used to avoid CORS, hide API keys, cache responses, and spread load across servers. Examples are Vite's server.proxy while developing, and Nginx, Netlify redirects, or a backend route in production.

5 Axios: a personal assistant ✓ complete

Analogy
An assistant makes the call for you. They open the bag automatically, tell you if the kitchen got your order wrong (they reject on 4xx/5xx), and show your membership card on every call without being asked (interceptors).

What it really is
A library that wraps HTTP requests. It's convenient, but it's extra code to ship. Why not just use fetch for everything? You can, and many teams do. Axios mostly saves you boilerplate. The real gaps in fetch show up after the data arrives, and Lesson 6 covers those.

⚠ Axios is a new dependency, so you could do this in a scratch file instead.

6 Server state vs app state: React Query and Zustand ✓ complete

Analogy
Zustand is not a fetching tool. It's the fridge: shared storage where every component in the house can grab things like a theme, a cart, or a selected city. It doesn't know or care where the food came from.

React Query is a smart fridge for food from kitchens. It remembers what you ordered, knows when it's gone stale and reorders, and doesn't order twice if two people ask at once. It also tracks "food is on its way" (loading) and "order failed" (error) for you.

Key idea
Data the server owns (the weather) needs different tools from data your app owns (which tab is open).

⚠ React Query is a new dependency.
